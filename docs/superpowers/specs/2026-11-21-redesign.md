# Bruinen redesign: design spec for implementation

This file tells Claude Code how to build the Bruinen redesign. It is the
written source for the design. The visual source is the design canvas:
<https://claude.ai/artifact/NVpjVtPDMzMvJwJAf3VZjo>.

Read this file fully before you change templates or CSS.

---

## 1. Scope

### 1.1 Screens in this spec

| Canvas artboard | Screen                               | Collection shown            |
| --------------- | ------------------------------------ | --------------------------- |
| `Main`          | Collection list, cards view, desktop | Books                       |
| `DesktopTable`  | Collection list, table view, desktop | Articles                    |
| `DesktopRecord` | Record page, desktop                 | Books → "Project Hail Mary" |
| `PhoneCards`    | Collection list, cards view, phone   | Books                       |
| `PhoneTable`    | Collection list, list view, phone    | Articles                    |
| `PhoneRecord`   | Record page, phone                   | Books → "Project Hail Mary" |

### 1.2 Screens not designed yet

Use the tokens and components in this file for these screens. Do not
invent new patterns.

- Sign in, Collections (home), Error page.
- Create dialog, Edit dialog, Scan dialog.
- The 640–1023 px layout (see section 4).
- Cards for 1:1 covers (CDs, Vinyls) and 63:88 cards (MTG).
- Table view for collections with images, on desktop.
- Empty states.

### 1.3 Rules from the original brief that stay

Do not break these rules. Automated tests check many of them.

- **No delete.** Do not add a delete control anywhere.
- **Server-rendered forms.** Every action is a real HTML form. JavaScript
  only makes it smoother. Everything must work without JavaScript.
- **Touch targets.** Every button, link, input and select is 44 × 44 px
  or larger.
- **WCAG.** The app must pass automated WCAG checks in light and dark
  mode.
- **Theme.** Light and dark follow the system setting. There is no theme
  toggle in the app. (The canvas has a "theme" tweak only for review.)
- **Breakpoints.** Below 640 px is the phone layout. From 1024 px the
  collection navigation is a sidebar.
- **URLs.** Search, sort, page and view stay in the URL.
- **Offline.** The service worker caches the app's own files and covers.
- **Copy changes.** Section 10 lists every copy change, so you can update
  the tests.

## 4. Layout and breakpoints

| Width       | Navigation                | Cards grid                      | Table view                       | Record page                |
| ----------- | ------------------------- | ------------------------------- | -------------------------------- | -------------------------- |

| ≥ 1024 px   | Sidebar, 248 px           | `auto-fill, minmax(164px, 1fr)` | Real table                       | Two columns (cover 288 px) |

The 640–1023 px layout is not drawn. Use the phone navigation with the
desktop content components.

## 5. Shell components

### 5.1 Skip link

- First element in `<body>`: `<a class="skip" href="#content">Skip to content</a>`.
- Hidden off-screen until focused. When focused: top-left, surface
  background, padding 12 px 16 px, radius 10 px.
- `<main id="content" tabindex="-1">`, so focus moves into the main area.

### 5.2 Header

- `<header>`, full width, height 64 px (phone 60 px), padding 0 24 px
  (phone 0 12 px 0 16 px), `--surface`, 1 px `--border` bottom.
- Left: home link (min-height 44 px) with the logo mark and the wordmark.
  - Logo mark: 32 × 32 px (phone 30 px), radius 9 px (phone 8 px),
    `--accent` fill, waves icon 18 px in `--accent-text`.
  - Wordmark "Bruinen": see typography.
- Right: Log out form (`method="post"`) with a button: log-out icon 18 px
  and the text "Log out".
  - Desktop: secondary button style, 1 px `--border`, 14 px, weight 500.
  - Phone: no border, transparent fill, `--muted` text.

### 5.3 Sidebar (≥ 1024 px)

- `<nav aria-label="Collections">`, `--surface`, 1 px `--border` right,
  padding 20 px 12 px.
- Three groups, in this order. Keep the brief's collection order inside
  each group.

| Group label | Collections                                                                      |
| ----------- | -------------------------------------------------------------------------------- |
| Physical    | Movies, Shows, Games, Books, CDs, Vinyls, MTG                                    |
| Digital     | Articles, Podcasts, Videos, Feeds, Read later, Watch later, GitHub, Work records |
| Vocabulary  | Meta                                                                             |

- Group label: `<p id="grp-physical">` (etc.), group-label style, padding
  6 px 12 px. The list: `<ul aria-labelledby="grp-physical">`. Margin
  18 px below each group.
- Item: `<a>` flex row, `justify-content: space-between`, min-height
  44 px, padding 0 12 px, radius 10 px, 15 px, weight 500,
  `1px solid transparent` border. Collection name on the left. Record
  count on the right (13 px, weight 500, `--muted`, tabular numbers).
- Hover: `--hover` fill.
- Current item: `aria-current="page"`, `--accent-soft` fill,
  `--accent-soft-text` text and count, weight 600, `1px solid --accent`
  border. The border and the weight mark the state, so colour is not the
  only sign.
- Counts are optional. If they make the page slow, remove them.

### 5.4 Pill navigation (< 1024 px)

- `<nav aria-label="Collections">`, `--surface`, 1 px `--border` bottom,
  horizontal scroll (`overflow-x: auto`), scrollbar hidden.
- `<ul>`: padding 10 px 16 px, gap 8 px, `width: max-content`.
- Pill: min-height 44 px, padding 0 16 px, radius 999 px, 15 px,
  `white-space: nowrap`, 1 px `--border` border, `--surface` fill,
  `--text`, weight 500.
- Current pill: `aria-current="page"`, `--accent-soft` fill,
  `--accent-soft-text`, 1 px `--accent` border, weight 600.
- Scroll the current pill into view on load (JavaScript, optional).

## 6. Content components

### 6.1 Heading row (collection list)

- Desktop: flex, wrap, `align-items: flex-end`,
  `justify-content: space-between`, gap 16 px, margin-bottom 24 px.
  - Left: H1 (collection name) and below it the count, "214 records"
    (15 px, `--muted`, margin-top 6 px).
  - Right: the Cards/Table switch (collections with images only) and the
    primary "Add {item}" button.
- Phone: H1 and count on one baseline row (gap 10 px). The switch is full
  width below. The Add button is the FAB (section 6.13).

### 6.2 Primary button

- `--accent` fill, `--accent-text`, no border, radius 12 px, 15 px,
  weight 600, gap 8 px, plus icon 18 px (stroke 2.4).
- Min-height 52 px in the heading row. 48 px on the phone record page.
- Hover: `--accent-hover`. Disabled: opacity 0.6.

### 6.3 Secondary button

- `--surface` fill, 1 px `--border-strong` border (header: `--border`),
  `--text`, radius 10 px (toolbar 12 px), 14–15 px, weight 600,
  min-height 44 px (toolbar 48 px), padding 0 14–18 px.
- Hover: `--hover` fill.
- Links that look like buttons use this style: Back, Next, cover upload
  label.

### 6.4 Cards/Table switch (segmented control)

- Show it only for collections with images.
- Container: `role="group" aria-label="View"`, flex, gap 4 px, padding
  4 px, radius 12 px, `--hover` fill.
- Each half is a link (it changes `view=` in the URL). Min-height 44 px,
  padding 0 16 px, radius 9 px, 14 px, gap 8 px, 16 px icon (grid or
  lines).
- Active half: `aria-current="page"`, `--surface` fill,
  `1px solid --control-border`, `--shadow-sm`, `--text`, weight 600.
- Other half: `1px solid transparent`, `--muted`, weight 500.
- Phone: full width, each half `flex: 1`, content centred. Margin-bottom
  12 px.

### 6.5 Search form (toolbar)

- `<form role="search" method="get">`. Desktop: flex, wrap, gap 12 px,
  margin-bottom 32 px (table view 24 px). Phone: column, gap 10 px. The
  input and the Search button share one row.
- Search input:
  - `<label for="q" class="sr-only">Search {collection}</label>`
  - `<input id="q" type="search" name="q" placeholder="Search {collection}">`
  - Height 48 px, radius 12 px, `1px solid --control-border`,
    `--surface`, padding-left 46 px (phone 42 px).
  - Search icon 18 px, `--muted`, absolute at left 16 px (phone 14 px).
  - Desktop: `flex: 1 1 320px`.
  - The 300 ms auto-search stays.
- Search button: secondary, height 48 px. It stays visible because it is
  needed without JavaScript.
- **Scan to search (phone, new feature):**
  - A 44 × 44 px icon button inside the right end of the input:
    `aria-label="Scan a barcode to search"`, scan icon 20 px in `--accent`,
    transparent fill. Input padding-right 52 px.
  - Show it only on collections with a barcode or ISBN field.
  - It needs JavaScript and a camera. Render it with the `hidden`
    attribute. Remove `hidden` with JavaScript only when the Scan dialog
    can work.
  - On a successful read: put the code in `q` and submit the form.
  - The search must match the barcode or ISBN field. Check that the
    collection's search fields include it.

### 6.6 Sort select

- Container: relative, flex, `align-items: center`. Desktop
  `flex: 0 0 280px`. Phone full width.
- Visible label inside the box:
  `<label for="sort">Sort by</label>`, absolute at left 16 px (phone
  14 px), 13 px, weight 600, `--muted`, `pointer-events: none`.
- `<select id="sort" name="sort">`: `appearance: none`, height 48 px,
  radius 12 px, `1px solid --control-border`, `--surface`, padding
  0 44 px 0 76 px (phone left 74 px), 15 px (phone 16 px).

### 9.2 Required patterns

- Skip link and `<main id="content" tabindex="-1">`.
- Landmarks: `<header>`, `<nav aria-label="Collections">`, `<main>`,
  `<nav aria-label="Pagination">`.
- `aria-current="page"` on the current collection and the active
  Cards/Table half.
- Selected states use a border and font weight, not only colour.
- Every input and select has a `<label>`. The sort label is visible.
- Icon-only buttons have an `aria-label`.
- Decorative SVGs have `aria-hidden="true"`.
- Hidden text gives the meaning of icon-only badges ("Favorite").
- External links say "(opens in a new tab)" in hidden text.
- Sorted table headers have `aria-sort`. The table has a caption.
- `color-scheme` follows the theme, so native controls match.
- The placeholder colour is `--muted` with `opacity: 1`.
- Reduced motion: no transforms or transitions. Toasts stay until
  dismissed.
- Every interactive element is 44 × 44 px or larger.
- Phone inputs are 16 px, so iOS does not zoom.
